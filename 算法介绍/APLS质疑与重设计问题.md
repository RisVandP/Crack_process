# APLS 质疑与重设计问题整理

## 1. 当前背景

当前确定性模型中，木板被等分为大小相同的木块，因此：

- 所有木块面积相同；
- 所有木块在不考虑裂缝时具有相同基准价值；
- 普通加工、精密加工的单位面积增值系数固定；
- 所有相邻木块同时精密加工的奖励使用统一默认值；
- 精度不一致损失也倾向于使用统一默认值；
- 木块之间的差异主要来自裂缝：
  - 是否有裂缝；
  - 裂缝严重程度；
  - 裂缝导致的实际价值降低；
  - 裂缝导致的加工时间增加。

因此，不能随意假设某些木块“自身价值更高”或某些相邻边“奖励更高”。如果木块实际价值不同，应当来自裂缝严重程度不同；如果加工时间不同，也应当来自裂缝严重程度影响。

## 2. 原 APLS 设计思路

APLS 原本被设想为在 MG 的基础上增加相邻精加工对候选。

MG 每轮只评价单块候选：

```text
a = (u, q, k)
```

APLS 额外加入相邻精加工对候选：

```text
c = (a_u, a_v)
a_u = (u, P, k)
a_v = (v, P, l)
{u,v} ∈ E
```

然后将单块候选和相邻对候选放入同一个候选池：

```text
C(S) = A1(S) ∪ A2(S)
```

并统一按照单位时间收益评分：

```text
g(c | S) = gain(c | S) / t(c)
```

其中：

```text
t(c) = t_{u,k}                         若 c 是单块候选
t(c) = t_{u,k} + t_{v,l}               若 c 是相邻对候选
```

这样做的初衷是避免相邻对候选因为一次包含两个加工任务而天然占优。

## 3. 目前发现的关键质疑

### 3.1 相邻奖励统一时，APLS 的优势是否充分？

如果所有相邻双精加工奖励都是同一个常数 `b`，那么不能用“某条相邻边奖励更高”来说明 APLS 优于 MG。

之前用“B11 与 B21 的奖励高，其他边奖励低”的例子是错误的，因为这违背了当前模型设定。

需要重新回答：

```text
在所有相邻边奖励相同的情况下，APLS 为什么仍然可能优于 MG？
```

如果无法清楚回答，就说明 APLS 当前设计的必要性不足。

### 3.2 木块基准价值相同时，不能随意假设木块自身价值不同

当前模型中，每个木块的基准价值相同。

如果某个木块实际价值较低，只能说明它受裂缝影响更严重：

```text
v_u = base_value × (1 - CS_u)
```

因此不能随意构造：

```text
B11: r = 8.8
B21: r = 8.8
B31: r = 9.5
```

除非同时解释这些差异来自不同的裂缝严重程度，并且该裂缝严重程度还会影响加工时间。

也就是说，若要构造例子，必须同时满足：

```text
实际价值差异来自 CS_u；
加工时间差异也与 CS_u 有关；
不能只单独修改收益而不修改时间。
```

### 3.3 MG 已经会动态感知相邻关系

MG 每轮会在当前方案 `S` 下重新计算候选收益。

如果某个木块 `u` 已经被精密加工，那么其相邻木块 `v` 的精密加工候选在下一轮会因为：

- 获得相邻双精加工奖励；
- 减少或消除精度不一致损失；

而评分提高。

因此，MG 并不是完全不能形成相邻精加工区域。

需要更准确地区分：

```text
MG 能逐步形成相邻精加工；
APLS 试图提前评估相邻双精加工；
但这种提前评估在当前统一奖励设定下是否有必要？
```

### 3.4 相邻对候选是否会引入偏置？

即使用单位时间收益归一化，相邻对候选仍然是一次改变两个木块的状态。

需要判断：

```text
APLS 是否仍会过度偏向相邻精加工对？
```

尤其是在：

- 相邻奖励 `b` 较大；
- 精度不一致损失 `p` 较大；
- 精密加工本身增值较大；

的情况下，相邻对候选可能频繁胜出。

这可能并不是算法能力提升，而是候选设计带来的结构性偏好。

## 4. 当前 APLS 叙事存在的问题

原叙事是：

```text
MG 只评价单块候选，可能错过相邻组合；
APLS 加入相邻精加工对候选，因此能得到更好方案。
```

但在当前模型设定下，这个叙事还不够严谨。

原因是：

1. MG 已经会动态更新相邻木块的候选收益；
2. 所有相邻奖励一致，不能假设某些边更值得成对加工；
3. 木块基准价值一致，收益差异必须来自裂缝；
4. 裂缝同时影响价值和加工时间，不能只单独设定收益；
5. 相邻对候选可能只是扩大搜索步长，而不是从根本上解决 MG 的明确缺陷。

## 5. 需要重新思考的问题

### 问题 1：APLS 的核心改进到底是什么？

可能的解释有两种：

```text
解释 A：APLS 是一种候选增强。
它在 MG 单块候选之外加入相邻双精加工候选，使搜索步长更大。

解释 B：APLS 是一种局部搜索增强。
真正有价值的不是成对构造，而是后续 PairInsert、Swap、Relocate 等局部搜索。
```

需要判断哪一个更符合项目目标。

### 问题 2：是否应该弱化“相邻对构造”的地位？

如果相邻对候选的理论优势不好证明，可以考虑：

- 第一阶段仍以 MG 为主；
- 相邻对候选只作为有限补充；
- 更强调第二阶段局部搜索；
- 把 APLS 定义为“MG + 相邻感知局部搜索”，而不是“相邻对优先构造”。

### 问题 3：APLS 是否应该从“成对加入”改为“局部邻域改进”？

也许更合理的设计是：

```text
先用 MG 生成初始方案；
再通过局部搜索修正 MG 的早期选择。
```

例如：

- 替换一个孤立精加工木块为两个相邻普通/精密组合；
- 释放一个低收益精密木块，加入一个相邻精加工对；
- 在相邻区域内调整普通/精密加工状态；
- 用 Swap 或 PairInsert 改善精密加工的空间连续性。

这样 APLS 的改进点会更像：

```text
MG 是构造型贪心，早期决策不可回退；
APLS 通过局部搜索允许撤销、替换和相邻组合插入。
```

这个叙事可能比“第一阶段加入相邻对候选”更稳。

### 问题 4：是否需要重新命名 APLS 的含义？

当前 APLS 被解释为：

```text
相邻成对局部搜索
```

但如果最终重点放在局部搜索，而不是成对构造，则可以考虑解释为：

```text
Adjacent Pair Local Search
```

重点是“相邻对作为局部搜索邻域”，而不是“每轮构造时优先加入相邻对”。

## 6. 可能的新叙事方向

更稳妥的 APLS 叙事可以是：

```text
MG 的不足：
MG 是逐步构造型贪心算法。虽然它会动态更新单块候选评分，
但一旦早期选择占用了精密设备时间，后续无法主动撤销或替换这些选择。
在裂缝分布不均、加工时间不同、精密设备紧张的情况下，
MG 可能形成局部最优方案。

APLS 的改进：
APLS 以 MG 方案为基础，引入相邻对相关的局部搜索邻域。
它允许算法在已有方案上进行释放、替换、成对插入和设备重分配，
从而修正 MG 的早期贪心决策。
```

这个叙事不依赖于：

- 不同相邻边奖励不同；
- 木块基准价值不同；
- 单独收益为负但成对收益为正；

因此更符合当前模型。

## 7. 当前需要继续讨论的核心问题

1. 是否保留 APLS 第一阶段中的“相邻精加工对候选”？
2. 如果保留，它只是候选增强，还是算法核心？
3. APLS 的主要优势是否应转移到局部搜索阶段？
4. APLS 是否应改为：

```text
MG 初始解 + 相邻对局部搜索
```

而不是：

```text
单块候选与相邻对候选联合构造 + 局部搜索
```

5. 如果要证明 APLS 比 MG 更有适用场景，应设计怎样的实验参数？
   这些参数必须符合：

```text
木块基准价值相同；
相邻奖励统一；
裂缝导致价值和时间差异；
精密设备时间有限；
```
